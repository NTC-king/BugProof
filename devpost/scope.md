# BugProof

Local evidence-driven checking of AI-proposed Python function repairs. Working name inherited from the displayed proposal; final public naming belongs to the entrant.

## The Unique Kernel
Distinguish a fix passing familiar examples from one surviving independent challenge cases, with exact evidence rather than a correctness probability.

## Who It's For
An AI-assisted Python learner evaluating a proposed repair.

## The Core Loop
Load or paste a function and explicit cases, run the original, obtain or paste a candidate, verify against locked examples/challenges, inspect and export results.

## Inspiration & Identity
The previously displayed research proposal recommends a calm, warm-neutral technical workbench with readable code and explicit verdict labels. This is an accepted assistant recommendation, not an independently elicited personal aesthetic preference.

## Why This Matters to the Learner
The entrant wants a working prize-competition project, learning, and portfolio evidence.

## What "Working" Looks Like
Real Python executes in a restricted browser worker. A labeled inadequate candidate fails a declared challenge; a correct candidate passes listed tests; evidence exports. Live AI repair is never simulated as live.

## The POC Boundary
One supported synchronous function, JSON arguments/results, explicit expected values/exceptions, editable examples/challenges, optional configured live provider, and local-only use.

## Later
Public hosting, richer Python compatibility, expanded datasets, extra model providers.

## Explicitly Cut
Repository agents, arbitrary package installation, host Python execution, accounts, billing, automated trading, and claims of formal verification.

## Approval Basis
The full proposal was displayed before implementation. The entrant replied 'alright start working' and subsequently explicitly requested coding without routine pauses. These artifacts distill that approved direction; no separate interview or hands-on review is being fabricated.
